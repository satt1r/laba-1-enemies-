# Лаба 3 — абстракция, наследование, полиморфизм

Задания 1–2 находятся в отдельном мини-проекте `TimedClicker.sln`. Задание 3 интегрировано в существующий `../Lab2.Clicker/Clicker.sln`. Структура первой лабораторной и общие `assets` сохранены.

## Проекты и запуск

- `TimedClicker.Core` — контроллер раунда, сферы, игрок и таймер перезарядки; обычная библиотека .NET 8 без WPF.
- `TimedClicker.App` — WPF-окно; передаёт время и координаты в контроллер и отображает его состояние.
- `TimedClicker.Checks` — консольные проверки без сторонних библиотек.

На Windows установите .NET 8 SDK. В Visual Studio откройте `TimedClicker.sln`, выберите `TimedClicker.App` запускаемым проектом и нажмите F5. Нужен компонент разработки классических приложений .NET.

Из корня репозитория:

```powershell
dotnet run --project Lab3.TimedClicker/TimedClicker.App
dotnet run --project Lab2.Clicker/Clicker.App
```

На Windows, macOS и Linux можно запускать проверки:

```sh
dotnet run --project Lab3.TimedClicker/TimedClicker.Checks
dotnet run --project Lab2.Clicker/Clicker.Checks
```

Сборка окон на macOS/Linux возможна, запуск WPF требует Windows:

```sh
dotnet build Lab3.TimedClicker/TimedClicker.sln -p:EnableWindowsTargeting=true
dotnet build Lab2.Clicker/Clicker.sln -p:EnableWindowsTargeting=true
```

В подготовленной облачной среде перед командами выполните `source /workspace/cloud-dotnet-env.sh`.

## Мини-игра

Кнопка «Начать заново» запускает новый раунд на 30 секунд и сбрасывает игрока, очки и бонусы. Новая сфера появляется раз в секунду, живёт 2–5 секунд, целиком помещается в игровую зону. Промах не даёт очков и не расходует перезарядку. При перекрытии собирается только верхняя сфера. После окончания раунда объекты исчезают и клики не принимаются.

| Обозначение | Действие |
| --- | --- |
| +, фиолетовая | Обычная сфера: `1000 / (диаметр × время жизни)` очков; бонусный вариант: 50 очков |
| К, синяя | Умножает интервал клика на 0.8, минимум 0.1 с |
| Ж, зелёная | Увеличивает множитель жизни следующих сфер на 0.25, максимум ×3 |
| С, оранжевая | Умножает интервал появления на 0.8, минимум 0.25 с |

Начальный интервал клика — 0.5 с. Бонусы мини-игры сохраняются до конца раунда. Уже появившиеся сферы сохраняют своё время жизни; ускорение появления применяется к следующему запланированному интервалу. Все параметры выбора баланса вынесены в небольшие классы.

## Перенос в основную игру

`Clicker.Core` ссылается на `TimedClicker.Core` и повторно использует `Collectable` и `Cooldown`; копий этих классов нет. Ссылка на проект добавлена в решение второй лабораторной. `BonusController` адаптирует появление и сбор сфер к бесконечной игре с противником.

- Начальный интервал атаки — 0.5 с. Повторная атака во время отсчёта не наносит урона и не выдаёт награду.
- Улучшение за 100 золота умножает постоянный интервал на 0.8; каждая следующая покупка вдвое дороже. Минимум — 0.1 с; после достижения предела золото не списывается.
- Раз в 3 секунды в зоне противника появляется случайная сфера. Если её не собрать, она исчезает через 6 секунд.
- `×2` удваивает урон на 8 секунд; `К` делит интервал следующих атак пополам на 8 секунд; `+З` сразу выдаёт пятикратную текущую награду противника.
- Временные бонусы хранятся отдельными объектами. Повторные множители перемножаются, каждый заканчивается независимо. Итоговый интервал ограничен снизу 0.05 с.
- Покупка или бонус изменяет интервал **следующих** атак; уже начатая перезарядка завершается по прежнему времени. Сбор сфер доступен и во время перезарядки атаки, сам по себе не атакует противника.
- Постоянный урон игрока не перезаписывается бонусами. Урон, золото и цены продолжают вычисляться через `BigNumber`; секунды хранятся в `double`.
- Загрузка JSON начинает новую сессию, включая сброс сфер, перезарядки и активных эффектов.

## Что объяснять на защите

1. **Абстракция:** `Collectable` содержит общие координаты, радиус, время жизни и защиту от повторного сбора. У базовой сферы нет универсального эффекта, поэтому `OnClick()` — абстрактный метод и `new Collectable(...)` запрещён.
2. **Наследование:** `PointsSphere`, `CooldownSphere`, `LifetimeSphere`, `SpawnSphere` и три сферы основной игры наследуют `Collectable`, вызывают его конструктор через `base(...)` и реализуют эффект через `override`.
3. **Полиморфизм:** контроллер хранит `List<Collectable>` и вызывает `TryCollect()`, который вызывает переопределённый `OnClick()`. В обработке кликов нет ветвления по типам. `switch` нужен только фабрике при случайном создании объекта.
4. **abstract и virtual:** у `OnClick()` нет тела, конкретный наследник обязан его реализовать. У `ActiveBonus.DamageFactor` и `CooldownFactor` есть нейтральное значение 1; они виртуальные, наследник меняет только нужный коэффициент.
5. **Перегрузка:** два конструктора `PointsSphere` отличаются набором параметров. Вариант выбирается при компиляции; конкретная версия `OnClick()` — при выполнении.
6. **sealed:** конкретные сферы объявлены `sealed`, поэтому дальше наследовать их нельзя. `sealed override` запретил бы только дальнейшее переопределение конкретного метода, сохранив возможность наследования класса. Здесь такой дополнительный уровень наследования не нужен.
7. **Отдельный таймер:** `TimedPlayer` и `Player` владеют объектом `Cooldown`, но не реализуют отсчёт самостоятельно. Таймер можно использовать независимо от игрока и проверять без окна.
8. **Время:** `DispatcherTimer` вызывает обновление, а фактически прошедшие секунды измеряет `Stopwatch`. Появление и исчезновение сфер обрабатываются контроллером по порядку даже при задержке UI-потока.

## Проверка на Windows перед сдачей

1. Запустить мини-игру, нажать «Начать заново», собрать обычную сферу, проверить рост очков и исчезновение сферы. Промахнуться — очки не меняются.
2. Быстро нажать на две сферы: вторая остаётся до окончания перезарядки. Проверить бонусы К, Ж, С и вариант +50.
3. Дождаться конца 30 секунд: поле очищено, счёт фиксирован. Начать заново — состояние сброшено. Изменить размер окна — круги остаются внутри поля.
4. Запустить основную игру: проверить изображение противника, обычный клик и блокировку быстрых атак. Собрать сферу — здоровье противника от этого не уменьшается.
5. Собрать ×2 и К, увидеть оба таймера; дождаться окончания одного — другой продолжает работать. После окончания обоих возвращаются постоянные параметры.
6. Получить золото, купить ускорение, проверить списание и новую цену. Проверить, что покупка урона по-прежнему работает.
7. Загрузить другой JSON во время бонуса: новая игра без старых эффектов и сфер. Закрыть окна: таймеры останавливаются.

Автоматически проверяются границы времени, повторные клики и сбор, истечение объектов, большие шаги времени, все эффекты через базовый тип, независимое истечение бонусов и покупка ускорения. В Linux прошли 31 проверка мини-игры и 4877 проверок основной игры; оба WPF-проекта собраны без ошибок и предупреждений. Ручная проверка окон Windows ещё требуется.

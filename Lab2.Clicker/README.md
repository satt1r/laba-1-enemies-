# Лаба 2 — игра-кликер

Откройте `Clicker.sln` в Visual Studio. Сейчас решение содержит библиотеку `Clicker.Core` и консольный проект `Clicker.Checks` для проверки её поведения. Игровое окно пока не добавлено.

## Готово: BigNumber и четыре арифметические операции

Число хранится в приватном массиве блоков от 0 до 999, младшим блоком вперёд. Например, `1 005 017` хранится как `[17, 5, 1]`. Конструктор читает строку по цифрам, без преобразования всего числа в стандартный числовой тип.

Объект не предоставляет способов изменить массив после создания. `ToString()` выводит старший блок как есть, остальные дополняет до трёх цифр: `1`, `005`, `017`.

Поддерживаются только неотрицательные целые числа. Ведущие нули убираются, ноль выводится как `0`. Пустая строка, пробелы, знак и любые символы кроме ASCII-цифр вызывают `FormatException`; `null` вызывает `ArgumentNullException`.

Операторы `+` и `-` используют приватные методы `Add` и `Subtract`. Сложение переносит избыток в следующий блок, вычитание занимает единицу у следующего блока. Каждая операция возвращает новый объект с собственным массивом, исходные числа не меняются. Результат меньше нуля вызывает `InvalidOperationException`.

Оператор `*` вызывает `Multiply`: каждый блок первого числа умножается на каждый блок второго с переносами, как при умножении в столбик. Оператор `/` вызывает `Divide`: деление уголком просматривает блоки от старшего к младшему, переносит остаток и подбирает каждый блок частного двоичным поиском в диапазоне `0..999`. Оба оператора принимают два `BigNumber` и возвращают новый объект.

Деление целочисленное: `10 / 3` даёт `3`, остаток отбрасывается. Деление на ноль вызывает `DivideByZeroException`. Дополнительно поддерживаются `BigNumber * int`, `int * BigNumber` и `BigNumber / int`; отрицательный целый операнд вызывает `ArgumentOutOfRangeException`. Эти перегрузки используют ту же поразрядную логику.

Дробный коэффициент можно представить отношением целых чисел: `value * 12 / 10` соответствует умножению на `1.2` с округлением вниз. Например, `1000` превратится в `1200`, а `1` останется `1` — это нужно учитывать при выборе начального урона и формул улучшения.

Сравнение сначала учитывает количество блоков, затем просматривает их от старшего к младшему. Доступны `CompareTo`, `==`, `!=`, `<`, `>`, `<=`, `>=`. `Equals` и `GetHashCode` учитывают значение числа, поэтому `0001` и `1` равны и подходят для хранения в `HashSet`. Сравнение порядка и арифметика с `null` вызывают `ArgumentNullException`; метод `CompareTo(null)` возвращает положительное значение по правилам `IComparable`.

Из корня репозитория:

```powershell
dotnet build "Lab2.Clicker/Clicker.sln"
dotnet run --project "Lab2.Clicker/Clicker.Checks/Clicker.Checks.csproj"
```

Проверки охватывают границу блока `999/1000`, внутренние и ведущие нули, числа длиннее `long`, ошибочные строки и независимость вывода от региональных настроек. Для арифметики проверяются переносы и заёмы через 1200 цифр, неизменяемость исходных чисел, отрицательный результат, сравнение и равенство. Проверяются умножение больших чисел, точное деление и деление с остатком, нулевое частное, деление на ноль и перегрузки с `int`. Ещё 200 пар чисел сверяются с обычной арифметикой в безопасном диапазоне, а для 25 больших примеров проверяется равенство `a = b * q + r` и ограничение `0 <= r < b`. В проверках небольших произведений `long` используется как независимый эталон; реализация `BigNumber` работает с блоками `int`, без `long`, `double` и `BigInteger`.

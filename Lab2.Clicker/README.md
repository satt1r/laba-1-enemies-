# Лаба 2 — игра-кликер

Откройте `Clicker.sln` в Visual Studio. Решение содержит WPF-приложение `Clicker.App`, библиотеку игровой логики `Clicker.Core` и консольный проект `Clicker.Checks` для проверок. Для запуска через F5 назначьте `Clicker.App` запускаемым проектом.

## Запуск игры

Из корня репозитория:

```powershell
dotnet run --project "Lab2.Clicker/Clicker.App/Clicker.App.csproj"
```

Нужны Windows и .NET 8 SDK либо более новый совместимый SDK. В Visual Studio должен быть установлен компонент «Разработка классических приложений .NET».

При сборке пример JSON из первой лабы и иконки копируются в `Assets` рядом с приложением. При запуске пример загружается автоматически. Клик по картинке наносит урон, победа приносит золото и сразу создаёт следующего противника. Кнопка улучшения доступна, когда золота хватает на покупку.

«Загрузить JSON» начинает новую игру с выбранными шаблонами. «Папка иконок» позволяет выбрать изображения для своих шаблонов. Если картинки лежат рядом с выбранным JSON, приложение использует эту папку автоматически. Иконки задаются именами файлов; пути к другим папкам в `IconName` не используются. При отсутствующей или повреждённой картинке остаётся кнопка с заглушкой — атака продолжает работать.

Числа длиннее девяти цифр отображаются сокращённо, например `1.00e120`. Полное точное значение видно во всплывающей подсказке при наведении на показатель. Все игровые расчёты используют `BigNumber`; числовая шкала здоровья 0..1000 нужна только для отображения.

## Готово: BigNumber и четыре арифметические операции

Число хранится в приватном массиве блоков от 0 до 999, младшим блоком вперёд. Например, `1 005 017` хранится как `[17, 5, 1]`. Конструктор читает строку по цифрам, без преобразования всего числа в стандартный числовой тип.

Объект не предоставляет способов изменить массив после создания. `ToString()` выводит старший блок как есть, остальные дополняет до трёх цифр: `1`, `005`, `017`.

Поддерживаются только неотрицательные целые числа. Ведущие нули убираются, ноль выводится как `0`. Пустая строка, пробелы, знак и любые символы кроме ASCII-цифр вызывают `FormatException`; `null` вызывает `ArgumentNullException`.

Операторы `+` и `-` используют приватные методы `Add` и `Subtract`. Сложение переносит избыток в следующий блок, вычитание занимает единицу у следующего блока. Каждая операция возвращает новый объект с собственным массивом, исходные числа не меняются. Результат меньше нуля вызывает `InvalidOperationException`.

Оператор `*` вызывает `Multiply`: каждый блок первого числа умножается на каждый блок второго с переносами, как при умножении в столбик. Оператор `/` вызывает `Divide`: деление уголком просматривает блоки от старшего к младшему, переносит остаток и подбирает каждый блок частного двоичным поиском в диапазоне `0..999`. Оба оператора принимают два `BigNumber` и возвращают новый объект.

Деление целочисленное: `10 / 3` даёт `3`, остаток отбрасывается. Деление на ноль вызывает `DivideByZeroException`. Дополнительно поддерживаются `BigNumber * int`, `int * BigNumber` и `BigNumber / int`; отрицательный целый операнд вызывает `ArgumentOutOfRangeException`. Эти перегрузки используют ту же поразрядную логику.

Дробный коэффициент можно представить отношением целых чисел: `value * 12 / 10` соответствует умножению на `1.2` с округлением вниз. Например, `1000` превратится в `1200`, а `1` останется `1` — это нужно учитывать при выборе начального урона и формул улучшения.

Сравнение сначала учитывает количество блоков, затем просматривает их от старшего к младшему. Доступны `CompareTo`, `==`, `!=`, `<`, `>`, `<=`, `>=`. `Equals` и `GetHashCode` учитывают значение числа, поэтому `0001` и `1` равны и подходят для хранения в `HashSet`. Сравнение порядка и арифметика с `null` вызывают `ArgumentNullException`; метод `CompareTo(null)` возвращает положительное значение по правилам `IComparable`.

Из корня репозитория:

```powershell
dotnet build "Lab2.Clicker/Clicker.sln"
dotnet run --project "Lab2.Clicker/Clicker.Checks/Clicker.Checks.csproj"
```

Проверки охватывают границу блока `999/1000`, внутренние и ведущие нули, числа длиннее `long`, ошибочные строки и независимость вывода от региональных настроек. Для арифметики проверяются переносы и заёмы через 1200 цифр, неизменяемость исходных чисел, отрицательный результат, сравнение и равенство. Проверяются умножение больших чисел, точное деление и деление с остатком, нулевое частное, деление на ноль и перегрузки с `int`. Ещё 200 пар чисел сверяются с обычной арифметикой в безопасном диапазоне, а для 25 больших примеров проверяется равенство `a = b * q + r` и ограничение `0 <= r < b`. В проверках небольших произведений `long` используется как независимый эталон; реализация `BigNumber` работает с блоками `int`, без `long`, `double` и `BigInteger`.

## Готово: игрок и активный противник

`Player` хранит золото, урон, цену улучшения и уровень как `BigNumber` со свойствами `private set`. Начальные значения: 0 золота, 10 урона, цена 100, уровень 1. Другие начальные значения можно передать в конструктор; урон и цена должны быть положительными.

- `AddGold(amount)` добавляет золото.
- `TryUpgrade()` возвращает `false` без изменения состояния, если золота недостаточно. При успехе списывает текущую цену, увеличивает уровень и пересчитывает урон и следующую цену.
- Урон растёт по формуле `damage * 12 / 10`. Следующая цена — `cost * 12 * level / 10`, где используется уровень до покупки. Из-за целочисленного деления рост округляется вниз; минимальная прибавка урона и цены — единица.

Например, при уроне 10 и цене 100 первые покупки дают урон `12, 14, 16, 19`, а следующие цены — `120, 288, 1036, 4972`.

`Enemy` представляет конкретного противника в бою, отдельно от шаблона первой лабы. Он хранит имя и иконку, максимальное и текущее здоровье, награду и вычисляемый признак `IsDefeated`. Текущее здоровье и награда имеют `private set`; начальное здоровье должно быть положительным.

`TakeDamage(damage, out reward)` уменьшает здоровье, не допуская отрицательного значения. Возвращает `true` и награду только при атаке, которая победила противника. До победы и при повторных атаках побеждённого противника возвращает `false` и нулевую награду. Вызывающий код передаёт полученную награду в `Player.AddGold`.

В `GameChecks` проверяются покупки при нехватке и точном количестве золота, рост значений выше диапазона `long`, минимальный рост после округления, обычный и избыточный урон, однократная награда и полный сценарий «бой — золото — улучшение».

## Готово: загрузка и выбор шаблонов

`EnemyCatalog.LoadFromJson(path)` загружает JSON того же формата, который сохраняет редактор первой лабы. `FromJson(json)` позволяет загрузить уже прочитанную строку. Базовые здоровье и золото читаются сразу в `BigNumber`, поэтому не ограничены диапазоном `int` или `long`.

`EnemyTemplate` хранит рецепт противника, а `EnemyCatalog` отдельно хранит его текущие характеристики на этапе. `CreateEnemy()` создаёт новый объект `Enemy`, используя случайное число от 0 до 1. Есть перегрузка `CreateEnemy(chance)` для проверки конкретных границ вероятностей. Повреждение созданного противника не влияет на шаблоны или других противников.

Шансы приводятся к сумме 1 при создании хранилища. Нулевые веса не участвуют в выборе, даже если выпало 0. Пустой список и список со всеми нулевыми шансами отклоняются. Веса сначала делятся на максимальный вес, чтобы их суммирование не переполнило `double`.

Первый этап использует базовые характеристики. После каждой победы вызывается `Advance()`: этап увеличивается, а здоровье и награда каждого шаблона умножаются на его модификаторы. Например, здоровье `100` с модификатором `1.2` меняется как `100 → 120 → 144`. Дробная часть отбрасывается на каждом этапе. Минимальное здоровье — 1, награда может быть нулевой. Нулевое базовое здоровье из редактора также заменяется на 1 при создании противника.

Коэффициенты из JSON читаются как `decimal` (до 28–29 значащих цифр), затем представляются отношением двух `BigNumber`. Умножение здоровья и золота выполняется собственной поразрядной арифметикой, без преобразования характеристик в стандартные числовые типы. Отрицательные коэффициенты и шансы, отсутствующие поля и некорректные числовые значения вызывают `InvalidDataException` при загрузке.

В `CatalogChecks` проверяются реальный JSON из первой лабы, границы вероятностей, нулевые шансы, масштабирование разных шаблонов, очень большие характеристики и ошибки загрузки.

## Готово: игровая сессия и окно

`GameSession` связывает игрока, текущего противника и хранилище шаблонов. `Attack(out reward)` наносит урон, начисляет награду при победе, увеличивает счётчик побеждённых и этап, затем создаёт нового противника. `TryUpgrade()` передаёт покупку классу игрока. Окно вызывает эти методы и обновляет отображение, не присваивая здоровье, золото или урон напрямую.

`SessionChecks` проверяет полный игровой цикл, награду за победу, смену этапа и характеристики следующего противника, покупку улучшения и сценарий на реальном JSON первой лабы.

## Проверка перед сдачей

1. Запустить `Clicker.App` и убедиться, что пример JSON и иконка загрузились автоматически.
2. С примером из репозитория сделать 10 кликов: получить 10 золота, увидеть второго противника и этап 2.
3. Довести число кликов до 100: получить 100 золота и купить улучшение. После покупки: золото 0, урон 12, уровень 2, следующая цена 120.
4. Загрузить свой JSON из первой лабы и выбрать папку иконок. Это начинает новую игру.
5. Проверить рост характеристик на шаблоне с модификаторами больше 1. В исходном примере оба модификатора равны 1, поэтому характеристики не увеличиваются.
6. Запустить `Clicker.Checks` командой выше и разобрать поразрядные операции `BigNumber` для защиты.

Игровой прогресс хранится в памяти до закрытия приложения. Сохранение прогресса условием не требуется.

Общие иконки и пример JSON находятся в `../assets/`. Редактор из первой лабы остаётся самостоятельным проектом в `../Lab1.EnemyEditor/`.
